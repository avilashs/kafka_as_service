# M2: placement

**Status:** implemented and tested on a real kube-apiserver (envtest). The real-scheduler run on kind is wired into CI; its result is recorded under [Results](#results) once it has run.

Acceptance (from the brief): *tests prove each invariant; the admission policy rejects deliberately bad pods; concurrent creates cannot oversubscribe.*

## Scope delivered

| Area | What exists |
|---|---|
| Dedicated tier | The API accepts `tier: dedicated`. Capacity is whole nodes per instance type and zone; a cluster reserves one node per broker and its pod must fit the node shape (`node_pools.node_cpu_milli / node_mem_mib`). Brokers render with the dedicated placement (own-owner node affinity, own taint toleration, anti-affinity against every broker of every tenant). |
| Node pools | `NodePoolProvider` interface (`internal/cloud`). **kind**: claims spare nodes (swaps the spare taint for the owner's taint and adds the owner labels in one update; returns them only after every pod is gone). **AWS**: renders one Karpenter v1 `NodePool` per dedicated cluster (`limits.nodes = brokers + surge`, owner label and taint, empty-only consolidation, one disruption at a time). The AWS manifest is unit-tested only. |
| Placement rules | `internal/placement`: one definition of six rules, used by the binding guard (hypothetical bind) and the auditor (actual state). Engine-neutral: it reads `required-pool` / `exclusive` / `cluster` / `role` labels, not Kafka names. |
| Admission policy | `deploy/admission/policies/`: CEL `ValidatingAdmissionPolicy` for pods in tenant namespaces (labels, node affinity pool, tolerations, hostname anti-affinity with `namespaceSelector: {}`, zone spread, `nodeName`, host access, privileged), plus node and namespace protection (only the provisioner may change pool labels/taints or the tenant-namespace label). |
| Binding guard | `internal/admission` + `cmd/streamcell-admission`: a `pods/binding` webhook that checks what already runs on the target node. Fails closed. Certificate job included. In-cluster manifests in `deploy/admission/workloads/`. |
| Audit | `streamcell-audit` CLI (exit 0 clean, 1 violations, 2 error) and the same code as the `placement-auditor` Deployment exporting `streamcell_placement_violations{rule,cluster,node}` plus last-success timestamps. Alert rules with a runbook for each; a unit test fails the build if an alert has no runbook or a rule has no documentation. |
| Delete | Pods get a 20 s grace on delete (engine-supplied `DeleteGraceSeconds`) so the 300 s graceful shutdown no longer dominates delete time (M1 finding). |

## How it is tested

`make e2e` (Postgres 17, Temporal dev server, **real kube-apiserver + etcd 1.34.1** with the Strimzi 1.3.0 CRDs). The shipped policy files are applied unchanged, so the CEL is evaluated by the real apiserver. Pods used in the policy and guard tests are built from the pod templates the Kafka engine really renders, so the renderer and the policy are tested against each other.

What is simulated in envtest (no kubelet, scheduler or controller-manager): `test/e2e/sim_test.go` marks `Kafka` Ready, finalizes empty Terminating namespaces and confirms pod termination (the kubelet's part). The "scheduler" in the placement tests is the test itself creating a `Binding`, which passes through the real admission chain.

The real scheduler, real Strimzi, and the in-cluster guard and auditor are exercised by `deploy/kind/smoke.sh` (CI job `kind-real-strimzi`).

## Bugs the tests found (and the fixes)

1. **Cruise Control and Entity Operator pods were rendered without the `required-pool` label.** Found by the admission suite; would have made the kind run fail. Fixed, with a unit test that every rendered pod template carries the placement labels.
2. **A scripted edit silently did nothing** because `gofmt` had changed the spacing the edit matched. Twice: the dedicated sizes' instance types, and the same label gap above. Both were caught by tests, not by the edit tool. Lesson recorded: scripted edits assert that they matched.
3. **Capacity check summed pods across groups** (found in M1; the per-group fix is what makes dedicated accounting correct).

## Known weaknesses and deviations (read these)

| Item | State | Plan |
|---|---|---|
| Guard across replicas | Per-node serialisation is in-process. Two replicas could admit two simultaneous conflicting binds. Needs a scheduler bug *and* a race; the auditor detects it. | Accept for v1, or add a lease per node (M6) |
| Guard certificate | 10-year self-signed, no rotation, no expiry alert. Expiry stops all binds in tenant namespaces (fail closed). | cert-manager + alert (M6) |
| Security-context rules | Not enforced. Strimzi mounts a `get nodes` service-account token into brokers (spike S-4). `runAsNonRoot` / seccomp / read-only root are to be decided from a real pod's security context, which the smoke test now prints. | M3 |
| `broker.rack` audit | Not implemented (needs a Kafka connection). Zone spread is audited by node zone. | M3 probes |
| Surge nodes | Not reserved in capacity; they use `limits.nodes` headroom. The "surge may last at most 2 h" timer is replaced by an alert that waits 30 minutes. | M4 with node rotation |
| Karpenter provider | Manifest unit-tested against the v1.15.1 field names; never applied to a real Karpenter/EKS. | M6 |
| Node labels at registration | Trusted: the node protection policy covers later changes only. | Consider `node-restriction.kubernetes.io/` prefixes in M6 |
| Terminating pods | The auditor ignores them, so a violation can hide for the length of a termination. | Accept |
| Provisioner identity | On kind the "provisioner" is the host `kubernetes-admin`; in a real cell it is the agent's ServiceAccount (the shipped default). | n/a |
| Namespace label as the policy scope | A tenant namespace that loses its `inventory` label leaves policy scope. The namespace protection policy blocks this for non-provisioners; the audit does not look at namespaces. | Add an audit rule if it matters |
| Delete speed fix | Unverified until the kind run completes (see Results). | |
